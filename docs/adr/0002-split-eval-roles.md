# ADR-0002 面试中的实时评估与面试后的报告评估分开配置模型

- 状态：提议（2026-10-17），实现评估器时（PR-11 之后）定稿
- 相关：PRD“双层 agent 的协作方式”“延迟预算”，[实测结论](../benchmarks/findings.md)，
  实测报告 [2026-10-17](../benchmarks/2026-10-17.md)、[2026-10-17_1651](../benchmarks/2026-10-17_1651.md)

## 背景

PRD 规定后台评估器异步运行：前台先说过渡语，评估器要在 **2.5 秒内**给出“追问还是换题”，
超时则前台按面试计划提下一题，评估结果只用于评分。PRD 同时规定：面试中的实时评分只用于决定追问，
报告里的最终得分在面试结束后基于全部转写重新评定（报告 60 秒内生成）。

目前只有一个评估角色 `llm_eval`（qwen3.8-max）。2026-10-17 实测：

| qwen3.8-max | 首 token P50 / P95 | 完整回答 P50（≤80 token） | 失败 | 同一回答 5 次打分 |
|---|---|---|---|---|
| 默认开思考 | 5536 / 10371 ms | 6422 ms | 打分 1/5 超时 | 7 7 7 7（均值 7.0） |
| 关思考 | 1128 / 2228 ms | 2006 ms | 0 | 8 8 8 8 7（均值 7.8） |

开思考时实时评估几乎必然超过 2.5 秒，“根据回答决定追问”这一核心体验会失效；
关思考快约 5 倍，但真实评估输出（得分、证据、下一步、追问要点）远长于 80 token，用 max 仍可能超时。
另外，开思考打分更严；不同型号给分水平也不同（flash 8.6–8.8、DeepSeek 8.0）。

## 决策（提议）

- 拆成两个角色：
  - **实时评估**（决定追问 / 换题）：优先试 **qwen3.8-flash 关思考**（完整回答 P50 约 1.3 秒），
    其次 qwen3.8-max 关思考；分数不对外展示，偏宽松可以接受。
  - **报告评估**（新增角色，如 `llm_report`）：qwen3.8-max 开思考，评分更严更稳，60 秒预算足够。
- 实时评估的 JSON 输出把“下一步动作”放在第一个字段，流式拿到即可决策，不必等证据写完。
- 最终报告固定用一个型号评分；切到备用模型时在报告里标明，避免分数不可比。

## 待验证

- 用评估器的真实提示词和结构化输出，实测 flash / max 关思考的完整耗时 P95 是否在 2.5 秒内。
- 实时评估与最终评分的一致性（同一场面试两者给分的差异）。
