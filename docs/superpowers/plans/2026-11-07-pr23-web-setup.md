## 2. OpenAPI 类型与 API 客户端

### 导出 schema

- 新增 `backend/tools/export_openapi.py`：用和 `test_api.py::make_settings()` 同样的方式在代码里构造最小 `Settings`（**不读 `.env`、不连数据库、不初始化观测**），`create_app(settings, resource_factory=<不会被调用的占位>, init_observability=False).openapi()`，按 `json.dumps(..., ensure_ascii=False, indent=2, sort_keys=True)` 写到参数给定的路径。不要启动 lifespan。
  - 如果 `make_settings` 那套构造需要的东西在 tools 里重复太多，可以把它挪到 `backend/src/interview/config.py` 之外的一个小模块里共用；但不要为此改 `config.py` 的行为。
- 产物 `web/openapi.json` 提交进仓库。
- 新增后端单元测试 `backend/tests/unit/test_openapi_snapshot.py`：调用同一个导出函数，与 `web/openapi.json` 比较，不一致时失败并提示“运行 make gen-types”。这样后端改了接口而忘了更新前端类型，`make check` 会挡住。

### 生成类型

- `pnpm gen-types` = `openapi-typescript openapi.json -o src/lib/api/schema.d.ts`；生成文件提交，并在 ESLint 配置里忽略它。
- Makefile：
  ```make
  gen-types:
  	$(UV) python tools/export_openapi.py $(abspath web/openapi.json)
  	pnpm --dir web gen-types
  ```

### 客户端 `web/src/lib/api/`

- `client.ts`：用 `openapi-fetch` 的 `createClient<paths>({ baseUrl })`。对外导出按业务命名的函数，页面不直接拼路径：
  - `uploadResume(file: File)`、`getResume(id)`、`updateResume(id, body)`
  - `parseJd(text)`
  - `createInterview(body)`、`getPlan(id)`、`updatePlan(id, questions)`
  - 类型全部从 `schema.d.ts` 的 `components["schemas"][...]` 取，不手写重复的接口类型。
- 每个函数都要有超时（`AbortSignal.timeout`），并且允许调用方传入自己的 `AbortSignal`（组件卸载时取消）。超时取值，常量集中写在一处并注明理由：
  - 简历上传解析 120 秒、JD 解析 90 秒（后端单次模型调用超时 30 秒，结构化输出最多重试 2 次）
  - 创建面试 240 秒（JD 解析 + 生成计划两段模型调用，都可能重试）
  - 其余读写 15 秒
- 失败统一转成 `ApiError`（`errors.ts`）：
  ```ts
  class ApiError extends Error {
    status: number | null;   // 网络错误 / 超时为 null
    code: string;            // 后端 error.code；网络错误 "network_error"，超时 "timeout"，取消 "aborted"
    traceId: string | null;  // body.error.trace_id，没有时取响应头 X-Request-ID
  }
  ```
  - 解析失败体的函数写成纯函数 `toApiError(status, body, headers)`，单独测试：body 是合法错误格式 / 不是 JSON / 缺字段 / 只有响应头里有 trace_id。
  - 网络错误的 message：“连不上后端服务，请确认已运行 make api”。超时：“请求超时，请稍后重试”。取消不显示给用户。
- 不要自动重试会花钱的请求（简历解析、JD 解析、创建面试），由用户点按钮重试。

### `/new` 准备流程

顶部显示 4 个步骤（简历 / 职位描述 / 面试设置 / 生成计划），当前步骤高亮；已完成的步骤可以点回去修改。

**第 1 步 简历**

- 文件选择只接受 PDF（`accept="application/pdf"`）；前端先检查扩展名/类型和大小（≤ 10 MB），不合格直接提示，不发请求。
- 上传中显示“正在解析简历（通常需要 10–30 秒）”和已等待秒数，按钮禁用。
- 成功后展示解析结果并允许修改：姓名；工作经历（公司、职位、起止、要点）；项目经历（名称、角色、技术栈、亮点）；技能；教育经历。列表项可增删。用户改过之后“保存修改”调用 `PATCH`（必须提交整份 `ResumeReplacement`），保存成功才允许进入下一步；没改过直接“下一步”。
- 空状态：某一类为空时显示“未识别到项目经历，可手动添加”这类提示，而不是空白。
- 后端校验规则以 schema 为准（如 `company`、`title`、`name`、`school` 至少 1 个字符）；前端在保存前做同样的非空检查并标出具体字段，避免拿到 422 才知道。
- 错误码要有对应的友好处理：`413`（太大）、非 PDF / 无文字 / 无法读取（看 `resume.py` 里各 `ResumeError` 子类的 code）、`parse_failed`（“简历解析失败，可重试”）、`model_unavailable`、`user_not_configured`（提示运行 `make seed`）。

**第 2 步 职位描述**

- 多行文本框，显示字数 `n / 10000`，超过上限不能提交；空白不能提交。
- “解析预览”调用 `POST /api/jd/parse`，显示岗位名称、级别、能力项列表（名称、描述、权重、考察要点）、技术术语标签。岗位名称或级别为空时显示“未注明”。
- 必须预览成功一次才能进入下一步；预览后再改文本，预览标记为过期，需要重新预览（或明确提示“文本已修改，请重新解析”）。
- 预览结果只用于展示，不传给创建接口（后端创建面试时会重新解析 JD，这一点写进汇报的“风险”）。

**第 3 步 面试设置**

- 类型：技术面 `technical` / 行为面 `behavioral`；风格：温和 `gentle` / 压力 `pressure`；语言：中文 `zh` / 英文 `en`；时长：15 / 20 / 30 分钟。
- 默认：技术面、温和、中文、20 分钟。用单选按钮组，不用下拉框。
- 选项的取值从 schema 类型来，中文名放在 `labels.ts`；TypeScript 用 `satisfies Record<...>` 保证枚举新增值时编译报错。

**第 4 步 生成计划**

- 汇总显示：简历姓名、岗位名称、四项设置。“生成面试计划”调用 `POST /api/interviews`（`resume_id`、`jd_text`、`type`、`style`、`language`、`duration_min`）。
- 生成中显示“正在生成面试计划（通常需要 30–90 秒，请不要关闭页面）”和已等待秒数；按钮禁用，防止重复提交。
- 成功后 `router.push(/interviews/{id}/plan)`。失败显示 `ErrorNotice`，可点“重试”。

### `/interviews/[id]/plan` 计划预览

- 进入时 `GET /api/interviews/{id}/plan`；加载中、404（“面试不存在”+ 返回 `/new` 的链接）、其他错误都要处理。
- 展示：
  - 阶段时间分配：按 `stages` 顺序列出阶段中文名和分钟数（`seconds / 60`，保留到 0.5 分钟），合计应等于设置的时长附近。
  - 能力项：名称、权重，`covered=false` 的标灰并注明“本场不考察”。
  - 题目：按阶段分组；**默认隐藏题目正文**（只显示序号、所属能力项、关联项目），顶部提示“题目默认隐藏，避免提前看到影响练习效果”。每题可以单独“展开”，也有“全部展开”。
- 修改（展开后）：题目正文、考察要点（≥ 1 条，可增删）、追问（2–3 条，可增删，到上下限时禁用对应按钮）；每题有“删除”。
  - 保存：把当前剩余的全部题目转成 `PlanUpdate`（只含 `id`、`text`、`key_points`、`follow_ups`，按当前顺序）调用 `PATCH`。转换写在 `lib/plan.ts` 的纯函数里并测试（去首尾空白、丢弃空行、保持顺序、删除的题不出现）。
  - 后端可能拒绝：`422 plan_invalid`（如删完某个必考能力项的题，后端会说明原因）原样显示 message；`409`（面试已开始或结束）提示“面试已开始，计划不能修改”，并把页面切到只读。
  - 有未保存修改时：“开始面试”禁用并提示先保存或放弃；提供“放弃修改”恢复到服务器版本；离开页面时用 `beforeunload` 提醒。
  - 不提供新增题目（后端不支持）。
- “开始面试”按钮跳转到 `/interviews/{id}/text`（占位页）。

### 通用

- `ErrorNotice`：显示 `message`；有 `traceId` 时显示“错误编号：xxxx”和复制按钮（`navigator.clipboard`，失败时选中文本即可）；可选“重试”按钮。不显示原始 JSON、不显示堆栈。
- 日志：不要 `console.log` 简历内容或 JD 原文。
- 简单可用即可：桌面宽度优先，窄屏不横向滚动；中文界面；不需要暗色模式。
- 可访问性基本要求：表单控件都有 `label`，按钮有明确文字，加载状态用 `aria-busy` / `role="status"`，错误用 `role="alert"`。
