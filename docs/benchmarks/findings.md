记录接入百炼、DeepSeek 时**实测得到、官方文档没有写清楚**的事实，以及据此做的设计取舍。

## 语音识别（fun-asr-realtime，华北2）

| 日期 | 结论 | 证据 | 影响 |
|---|---|---|---|
| 2026-10-17 | **按发送的音频时长计费，静音也算钱**，不是按有效语音、也不是按连接时长 | 100.29 秒录音，每句最终结果的 `usage.duration` 依次为 3、16、31、39、47、71、80、95，与各句结束时间（含句间停顿）吻合 | 一场 30 分钟面试全程开识别约 0.6 元；只在候选人说话时开启约减半（PR-27 接 LiveKit 时注意） |
| 2026-10-17 | `usage.duration` 是**截至该句结束的累计值**，取整到秒；**最后一句之后的音频不再报** | 同上，最大值 95 秒，实际发送 100.29 秒 | 计费时长取 max(最大 duration, 已发送音频时长)（`bailian_asr.py`） |
| 2026-10-17 | 结尾的噪声、尾音会产生**文本为空的最终结果** | 95.2 秒、99.4 秒处两条空结果 | 适配器不输出空文本结果，用量照常累计 |
| 2026-10-17 | **不返回语种字段** | 所有结果的 language 为空 | 中英混说不能靠识别结果判断语种 |
| 2026-10-17 | 中英混说识别准确：Python、FastAPI、PostgreSQL、Outbox Pattern 等都对；“MySQL”曾被识别成“My呃circle” | live 测试两次 | 热词有价值 |
| 2026-10-17 | **热词效果尚无定论**：第一次无热词 1.9% → 有热词 1.3%（术语 15/17 → 16/17），第二次两者都是 1.6%（术语都是 16/17）；同一条录音、同样条件，两次无热词的结果就差 1 处错误，**识别本身的波动已经和热词带来的差别一样大** | 两次实测（16:34、16:58）；参考文本已人工核对 | 只有 1 条录音无法判断热词效果，需要 10–20 条样本；仍计划按 JD 和简历动态生成热词 |
| 2026-10-17 | 连接复用正常：任务结束后在同一连接上开新任务 | live 测试第二个任务 | — |
| 2026-10-17 | 首个结果耗时受录音开头静音影响（第一句从 480 ms 开始），单次 246–980 ms 波动；246 ms 那次很可能计入了一条空结果 | live 测试三次 | 体验上更该看“说完到最终结果”的耗时，需要结尾不留长静音的多条录音才能测准 |

## 语音合成：CosyVoice（cosyvoice-v3-flash，任务协议）

| 日期 | 结论 | 证据 | 影响 |
|---|---|---|---|
| 2026-10-17 | **计费字符：汉字计 2，中英文标点、英文、数字计 1** | 41 字中文句（37 汉字 + 4 标点）计 78；83 字符英文句计 83 | 估计规则见 `bailian_tts.estimate_characters` |
| 2026-10-17 | `usage.characters` 是任务内累计值；**取消后的 task-finished 不带用量** | live 取消测试 | 取消时按已发送文本估计计费字符 |
| 2026-10-17 | `finish-task` 带 `directive: "cancel"` 能立即停止，**取消后连接可复用** | 取消后下一句首包 338–343 ms，无重连 | 打断（barge-in）成本低 |
| 2026-10-17 | **首包取决于第一句的长度**：服务端等到句末标点才开始合成 | 中文首包 263–376 ms；83 字符英文长问句 870–1701 ms | 面试官第一句话要短（PR-18） |
| 2026-10-17 | 四个候选音色（longanlang_v3、longshuo_v3、longanwen_v3、longxiaoxia_v3）听感偏“AI” | 人工试听 | 改用 Qwen3-TTS 音色，见 ADR-0001 |

## 语音合成：Qwen-TTS Realtime（qwen3-tts-flash-realtime，Realtime 协议）

| 日期 | 结论 | 证据 | 影响 |
|---|---|---|---|
| 2026-10-17 | Ryan、Bodega 等 Qwen3-TTS 音色**只能走这个协议**；它是纯合成模型，**级联架构可直接用**，不需要端到端 | 官方音色列表 | 新增 `bailian_realtime` 适配器 |
| 2026-10-17 | `response.done` 的 `usage.characters` 是**整个会话（连接）的累计值**，逐个相加会多算一倍多 | 中文 22 → 78，接着英文 84 → 162 | 按连接记住上一次累计值，本次取增量；计数规则与 CosyVoice 相同 |
| 2026-10-17 | `usage` 里还有 token 数（input / output / audio tokens），目前不用于计费 | 诊断脚本 | 单价按字符计（1 元/万字符） |
| 2026-10-17 | **没有取消当前合成的指令**，打断只能断开连接 | 官方客户端事件文档 | 打断后下一句要重新建连，可调用 `warmup()` 预建 |
| 2026-10-17 | **偶发卡住**：文本发完后 10 秒内服务端没有任何消息，约 3/14 次，未能稳定复现；之后一次 20 句实测 0 失败 | live 测试与诊断脚本 | 卡住时记录 `tts_realtime_stalled` 日志（已提交句数、完成句数、最近事件）；需要持续观察卡顿率 |
| 2026-10-17 | 音色本身语速偏慢：中文净语速 Ryan 5.3 字/秒、Bodega 4.3 字/秒（CosyVoice 6–7.6）；`speech_rate` 有效，Ryan 1.2 倍约 7 字/秒 | 试听样本的静音分析 | 当前配置 `speech_rate=1.2` |
| 2026-10-17 | **Bodega 每次生成的语速差异很大**，同一句英文 5.2–7.8 秒，1.2 倍有时比 1.0 倍还慢 | 两轮样本对比 | 语速参数对 Bodega 只能大致调整 |
| 2026-10-17 | 首包 P50 363 ms、P95 692 ms（中文 348 / 400，英文 408 / 704）；以 “Great.”“Okay.” 开头的英文句首包 228–266 ms，长问句 650–715 ms | 20 句实测 | 再次印证“第一句要短” |
| 2026-10-17 | 百炼**没有印度口音英语**的系统音色（英文只标注美式；口音音色有西班牙、意大利、法国、德国、韩国等） | 官方音色列表 | 需要时可选：声音复刻（需本人授权）、声音设计、接 Azure / Google 的 en-IN 语音 |

## 大模型

| 日期 | 结论 | 证据 | 影响 |
|---|---|---|---|
| 2026-10-17 | 前台 qwen3.8-flash（关思考）首 token P50 493–598 ms、P95 913–1045 ms，**一次运行中 20 次有 1 次超时（30 秒无响应）** | 两次实测 | 卡在 PRD 500 ms 预算线上；备用模型是刚需 |
| 2026-10-17 | 备用 deepseek-flash（关思考）首 token P50 551–619 ms、P95 756–808 ms，40 次无失败，最稳定 | 两次实测 | — |
| 2026-10-17 | 评估 qwen3.8-max **默认开思考：首 token P50 5536 ms、P95 10371 ms，打分时 1/5 超时**；关思考后 P50 1128 ms、P95 2228 ms、完整回答（≤80 token）P50 2006 ms，无失败 | 两次实测对比 | PRD 要求实时评估 2.5 秒内返回，开思考几乎必然超时；见 ADR-0002 |
| 2026-10-17 | 打分稳定性都好（标准差 ≤ 0.55），但**不同型号给分水平不同**：同一段回答 flash 8.6–8.8、DeepSeek 8.0、max 开思考 7.0、关思考 7.8 | 两次实测 | 最终报告评分固定一个型号；切到备用要标明；实时评估的分数不对外展示 |
| 2026-10-17 | 不同时段、网络下首 token 有约 100 ms 波动；单次测量还出现过 588–2001 ms 的大幅波动 | live 测试与两次实测 | 结论以多次运行为准 |
| 2026-10-17 | **JSON 模式三家都可用**：`response_format={"type": "json_object"}` 经 extra_body 传入，百炼 flash、开思考的 max、DeepSeek 都一次输出合法 JSON（无重试）；完整结构化输出（约 3 个字段）耗时 flash 2.8 秒、DeepSeek 2.1 秒、max 开思考 14.7 秒 | live 测试 test_structured_live（单次） | 实时评估用 flash 也接近 2.5 秒上限，ADR-0002 需要用真实评估器输出再测；结构化输出一律再经 Pydantic 校验 |
| 2026-10-17 | DeepSeek 默认开启思考，用 `thinking: {"type": "disabled"}` 关闭；百炼用 `enable_thinking: false` | 官方文档 + 实测用量中 reasoning_tokens 为 0 | 已写入角色默认 EXTRA_BODY |
| 2026-10-18 | **真实评估器输出（约 290 token）在百炼上都达不到 2.5 秒**：`evaluate()` 完整耗时 max 关思考 P50 6232 / P95 7743 ms（15 次，无重试）；flash 关思考单次调用 P50 8306 ms，比 max 还慢 | `test_evaluator_live.py`（9bc310b）15 次；另用同一提示词直接调用各 5 次 | 实时评估不能用百炼的这两个型号，见 [challenges.md C1](../challenges.md) |
| 2026-10-18 | 慢在**出字速度**，不在首 token：首 token 三家都是 0.6–0.75 秒；之后每个输出 token max 约 18 ms、flash 约 14 ms、deepseek-flash 约 4 ms | 同一提示词（输入约 1200 token）直接调用各 5 次，按（完整耗时 − 首 token）/ 输出 token 计算 | 输出越长越慢；精简输出字段对百炼型号帮助有限，对 DeepSeek 有效 |
| 2026-10-18 | **flash 输出更啰嗦**：同一题输出 380–613 token（max 约 290），且追问方向常常照抄要点原文（6 次里 3 次含“扩容或限流”），被校验拦下后连续 3 次都改不过来，15 次评估直接失败 | 同上；live 测试 flash 第一次即抛 `StructuredOutputError` | flash 不适合做评估器 |
| 2026-10-18 | **deepseek-flash 关思考最快**：`evaluate()` 完整耗时 P50 2194 / P95 3867 ms（15 次）；15 次里 6 次因追问方向含要点原文触发一次格式重试，每次多约 1.5 秒；不重试的 9 次都在 1.6–2.4 秒 | `test_evaluator_live.py` 15 次 + 10 次统计重试原因 | 唯一接近 2.5 秒的型号；减少重试是压 P95 的关键 |
| 2026-10-18 | 打分水平：同一段回答 max 15 次都给 4 分，deepseek-flash 13 次 3 分、2 次 4 分；证据都有效，没有触发证据重评 | 同上 | 实时评分只用于决定追问，不对外展示，偏严可以接受；报告评分仍固定一个型号 |
| 2026-10-19 | **改成“泄露要点不重试”后，deepseek-flash 关思考 `evaluate()` P50 1958 / P95 2692 ms**（15 次，格式重试 0 次）；另 20 次 P50 2099 / P95 2340 / 最慢 2390 ms，其中 1 次因追问方向含要点被改成换题 | `test_evaluator_live.py` 15 次（经 `live_eval_llm()`）+ 20 次统计 `override_reason` | P95 从 3.9 秒降到约 2.5 秒；已设为 `llm_live_eval`，见 [ADR-0002](../adr/0002-split-eval-roles.md) |

## 对照 PRD 延迟预算（候选人说完 → 听到面试官首个字）

| 环节 | 预算 | 2026-10-17 实测 | 结论 |
|---|---|---|---|
| 轮次判定 | ≤ 300 ms | 未测（PR-27） | — |
| 识别最终结果 | ≤ 200 ms | 109 ms（1 条录音，结尾有长静音） | 证据不足 |
| 前台首 token | ≤ 500 ms | P50 493–598 / P95 913–1045 ms | 卡线，P95 超 |
| 合成首包 | ≤ 200 ms | P50 363 / P95 692 ms | **超预算** |
| 网络 | ≤ 150 ms | 未单独测 | — |
| 合计 | P50 ≤ 1.2 s | 估算约 1.4 s | **P50 超** |

补救方向：过渡语（PRD I7，“嗯，明白了”）提前合成并缓存，候选人说完立即播放；让面试官第一句话短；前台超时自动切备用。

## 单价与计费口径的不确定项

- qwen3.8-flash / qwen3.8-max 的隐式缓存命中单价官方未公开（文档写“见控制台”），`pricing.yaml` 暂按输入单价估计（偏高）。
- DeepSeek 分高峰（北京时间工作日 9–12、14–18 点）和空闲时段，单价表不支持按时段计价，一律按高峰价（偏高）。
- qwen-audio-3.1-tts-flash 按 token 计费，单价表未填；用到时会报缺价格。
- 识别在取消、合成在取消时服务端是否仍按已收到的全部内容计费，文档未说明；当前按“已发送内容”估计（上限）。
- 百炼新用户免费额度不计入估算，实际账单以控制台为准。
